# اعلان‌های صوتی اسکنر حضور و غیاب — buzzer + سه صدای ضبط‌شده

نسخه: سایت **4.152.0** · دسکتاپ **2.83.0** (اصلاح هم‌نسخه، بدون انتشار جداگانه)
تاریخ: ۲۰۲۶-۰۹-۲۰/۲۱ · شاخه: `arena/01a0b793-baci`
سوئیت آزمون: `tests/test-scanner-sounds.mjs` (۱۵ بررسی) · شناسهٔ کش صفحه: `v=4.152.0-camera9-sounds`

## ۱) درخواست کاربر (عین متن)

> «سه فایل صوتی … برای اعلان‌های اسکنر حضور و غیاب … ۱) `net.ogg` برای خطای شبکه جایگزین buzzer دستگاه اسکن شود.
> ۲) `hzr.ogg` برای اعلام حضور به موقع، البته buzzer باشد و بعد از آن این صدای صوتی پخش شود.
> ۳) `tkhr.ogg` برای اعلام تاخیر، که این هم buzzer بزند ابتدا سپس این صوت پخش شود.
> هر سه فایل را هم در فایل های زیپ که می سازی قرار بده.»

## ۲) رفتار پیاده‌شده (دقیقاً همان ترتیب خواسته‌شده)

| رویداد اسکن | buzzer | صدای ضبط‌شده | ترتیب |
|---|---|---|---|
| **حضور به موقع** (`code=present`) | ✅ دو تنی (E6 → B6) — بدون تغییر | `hzr.ogg` | **اول buzzer، ۰٫۰۶ ثانیه سکوت، بعد صدا** |
| **تأخیر** (`code=late`) | ✅ دو بیپ میانی (۷۴۰Hz) — بدون تغییر | `tkhr.ogg` | **اول buzzer، ۰٫۰۶ ثانیه سکوت، بعد صدا** |
| **خطای شبکه** (نرسیدن/دفع پاسخ، timeout، خطای XHR) | ❌ **هیچ buzzerی زده نمی‌شود** | `net.ogg` | **فقط صدا، به‌جای buzzer** |
| تگ تکراری | ✅ (بیپ هشدار) | — | مثل قبل؛ صدای ضبط‌شده ندارد |
| کد نامعتبر / خطای سرور (پاسخ ۵۰۰ یا خروجی غیرJSON) | ✅ (BZZT خطا) | — | مثل قبل؛ «خطای سرور» ≠ «خطای شبکه» |
| تگ آزمایشی «حضور به موقع» / «تأخیر» | ✅ | `hzr.ogg` / `tkhr.ogg` | همان مسیر تگ واقعی (آزمون کل زنجیره) |

- **«جایگزین buzzer» در خطای شبکه** یعنی: پیام صوتی خودش اعلام خطاست و به‌جای buzzer پخش می‌شود، نه بعد از آن. (اگر بعد از buzzer بود، شکست شبکه شبیه «تأیید» شنیده می‌شد.)
- buzzerها **دست‌نخورده**اند (`buzzOk` / `buzzWarn` / `buzzErr` همان فرکانس‌ها و پوش صوتی قبل را دارند)؛ فقط یک پارامتر تأخیر اضافه شده تا صدا دقیقاً بعد از پایان buzzer شروع شود.
- لرزش گوشی (`navigator.vibrate`) هم مثل قبل کار می‌کند.

## ۴) چطور پخش می‌شود (و چرا این‌طور)

- همان `AudioContext` که buzzer از آن استفاده می‌کند، سه فایل را یک بار دانلود (`GET` با `responseType=arraybuffer`)
  و یک بار `decodeAudioData` می‌کند و سپس با `createBufferSource` پخش می‌کند — یعنی **یک دستگاه صوتی، یک مسیر**،
  بدون دو اکوسیستم صدای موازی.
- **پیش‌بارگذاری:** دانلود در همان لحظهٔ بالا آمدن صفحه شروع می‌شود (همراه باز شدن دوربین، نه روی مسیر بحرانی
  اسکن)؛ **decode** بعد از نخستین لمس صفحه انجام می‌شود، چون مرورگرهای موبایل تا تعامل کاربر اجازهٔ پخش نمی‌دهند.
- اگر تگ درست در همان ثانیه‌های اول (پیش از رسیدن فایل‌ها) اسکن شود، به‌محض آماده شدن فایل، صدای همان اسکن
  پخش می‌شود — ولی فقط اگر کمتر از **۱٫۵ ثانیه** گذشته باشد؛ صدای کهنه برای اسکن قدیمی پخش نمی‌شود
  (اعلام اشتباه بدتر از سکوت است).
- **تخریب تدریجی (همه روی گوشی‌ها):**
  1. WebAudio + decode Vorbis → پخش با تأخیر دقیق بعد از buzzer (مسیر اصلی).
  2. اگر decode شکست بخورد (مرورگر Vorbis ندارد) → عنصر `<audio>` همان فایل (پخش چند صد میلی‌ثانیه بعد از buzzer).
  3. اگر هیچ‌کدام نبود یا فایل ۴۰۴ بود → **بی‌صدا ولی سالم**: buzzer و اسکن بدون هیچ خطا و هیچ اختلالی کار می‌کنند.
- هیچ‌کدام از این مسیرها روی نخِ اسکن/شبکه اثر ندارد؛ خطای صدا هرگز باعث از دست رفتن یک اسکن نمی‌شود.
- نسخهٔ ES5 و XHR کنترلر حفظ شده است (بدون `fetch`/`Promise`/کتابخانه) تا گوشی‌های قدیمی هم همان فایل را اجرا کنند.
- اسکنر قدیمی (`attendance-scanner-legacy.php`) و بستهٔ پشتیبانش دست‌نخورده است؛ صداها مخصوص اسکنر جدید (`camera9-sounds`) هستند.

## ۶) آزمون‌ها

```bash
cd tests
node test-scanner-sounds.mjs                                          # ۱۵ بررسی تازه
SITE=.cache/site-full PATCH=update-v4.152.0 node test-scanner-lifecycle.mjs
SITE=.cache/site-full PATCH=.cache/cumulative-site bash ../scripts/run-tests.sh   # ۳۵/۳۵ سوئیت
python3 test-scanner-packaging.py                                     # ۶ بررسی بسته‌بندی
```

- `test-scanner-sounds.mjs` **کنترلر واقعی نسخهٔ ارسالی** را در یک مرورگر شبیه‌سازی‌شده اجرا می‌کند و ترتیب
  صداها را از فراخوانی‌های واقعی `createOscillator`/`createBufferSource` می‌خواند: buzzer قبل از صدا در
  «حضور به موقع» و «تأخیر» (با زمان شروع پس از پایان buzzer)، **نبود buzzer در خطای شبکه و پخش `net.ogg` به‌جایش**،
  خطای سرور/تگ تکراری/کد نامعتبر بدون صدای ضبط‌شده، تگ آزمایشی با همان صدا، یک‌بار پخش برای هر اسکن،
  مسیر «فایل دیرتر آماده شد» و «فایل خیلی دیر شد (پخش نمی‌شود)»، نبود WebAudio و `<audio>` (بی‌صدا و سالم)،
  شکست decode و بازگشت به عنصر `<audio>` با همان ترتیب، فایل ۴۰۴ (سکوت سالم) و مسیر قابل‌تنظیم صداها.
- `test-scanner-lifecycle.mjs` (۸۴ سناریو) یک بررسی تازه گرفت: پیش‌بارگذاری صداها دقیقاً سه درخواست `GET` است و
  هیچ اسکن حضوری نمی‌فرستد؛ هدف‌گیری درخواست‌ها هم از «اولین درخواست» به «درخواست‌های POST» تصحیح شد.
- آزمون بسته‌بندی اسکنر (۶ بررسی، شامل بررسی تازهٔ صداها) مطمئن می‌شود سه فایل `.ogg` **مو‌به‌مو همان فایل‌های
  ارسالی** در بستهٔ سایت، بستهٔ دسکتاپ، بستهٔ آنلاین و بسته‌های جمعی/Release هستند.
- **۳۵/۳۵ سوئیت پروژه سبز** روی همین بسته‌ها (شامل ۶۴ بررسی ورود مدیر به ربات و ۶۰ بررسی تگ آزمایشی).

## ۷) آنچه در این محیط آزموده نشده

- پخش واقعی صدا روی گوشی/تبلت مدرسه: اینجا با موتور صوتی شبیه‌سازی‌شده سنجیده شده است. بررسی نهایی با همان
  تگ آزمایشی روی گوشی واقعی است؛ اگر صدایی شنیده نشد، اول یک بار صفحه را لمس کنید و بعد `?debug=1` را ببینید.
- Safari قدیمی/iOS قدیمی که Vorbis را در WebAudio پشتیبانی نمی‌کند: مسیر جانشین (`<audio>`) آزموده شده، ولی
  رفتار همهٔ نسخه‌های مرورگر در این محیط قابل اجرا نیست.
- بلندی صدا در محیط پرصدا: `SOUND_GAP`/میزان صدای buzzerها قابل تنظیم است (در بالای فایل کنترلر).
