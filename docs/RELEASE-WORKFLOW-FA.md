# رویهٔ ثابت انتشار و تحویل — هر دستور، هر تغییر

> این فایل قرارداد کاری است که برای **همهٔ دستورات بعدی** اجرا می‌شود.
> هیچ تغییری بدون این چهار قلم «تمام» حساب نمی‌شود.

---

## برای هر تغییر، این ۵ قدم همیشه انجام می‌شود

### ۱) پوشهٔ `update-v<نسخه>/`
فقط فایل‌هایی که عوض شده‌اند، با همان چیدمان سایت، به‌علاوهٔ:

```
update-v4.126.0/
├── online-exam-take.php
├── online-exam-api.php
└── راهنمای-بروزرسانی.txt      ← فارسی: علت باگ، چه عوض شد، راهنمای نصب، نتیجهٔ تست
```

### ۲) فایل زیپ سایت در ریشهٔ ریپو
```
MODIFIED-FILES-v<نسخه>.zip     ← کپی بایت‌به‌بایت همان پوشه
```
با `zip -qry` ساخته و با `unzip -t` سالمی‌سنجی می‌شود.

### ۳) بستهٔ کامل دسکتاپ
```
SchoolDeskPro-v<نسخه>-win64.zip
```
ساخته‌شده از بستهٔ نسخهٔ قبل با تعویض payload و bump نسخه در `README.txt`.
**کنترل اجباری:** شمار ورودی‌ها باید برابر بماند و `diff` فهرست دو نسخه باید
دقیقاً همان فایل‌هایی را نشان دهد که عمداً عوض شده‌اند.

### ۴) commit + push روی شاخهٔ کاری
```
git push origin arena/01a0934a-baci
```
و PR به `main` (نمی‌توان مستقیم به `main` push کرد).

### ۵) لینک دانلود — **همیشه**
سرور دانلود روی پورت ۸۰۰۰ بالا می‌آید و لینک در پاسخ داده می‌شود:

```
https://8000-<sandboxId>.e2b.app/                                  ← فهرست کامل
https://8000-<sandboxId>.e2b.app/MODIFIED-FILES-v<نسخه>.zip        ← فایل‌های سایت
https://8000-<sandboxId>.e2b.app/SchoolDeskPro-v<نسخه>-win64.zip   ← بستهٔ دسکتاپ
```

> ⚠️ `sandboxId` در هر نشست عوض می‌شود، پس لینک هر بار از `E2B_SANDBOX_ID`
> خوانده و تازه تولید می‌شود — لینک کهنهٔ نشست قبل کار نمی‌کند.
> پوشهٔ `.arena/` هم بین نوبت‌ها پاک می‌شود، پس سرور هر نشست دوباره بالا می‌آید.

هر دو لینک با `curl` تست می‌شوند: `HTTP 200` + حجم بایت‌به‌بایت + تطابق SHA-256
دانلود با فایل روی دیسک.

## شماره‌گذاری نسخه

| | قاعده | نمونه |
|---|---|---|
| سایت | `4.<n>.0` — ادامهٔ رشتهٔ بالادستی | ۴.۱۲۶.۰ |
| دسکتاپ | `2.<n>.0` | ۲.۵۷.۰ |

یک تغییر سایت → bump هر دو، چون بستهٔ دسکتاپ همان سورس سایت را حمل می‌کند.

---

## تعریف «تأیید شده»

یک تغییر وقتی تأیید شده است که **کد واقعی اجرا شده باشد**:

| لایه | ابزار | چرا |
|---|---|---|
| PHP سرور | هارنس `@php-wasm/node` + SQLite | باینری PHP در این محیط نیست |
| جاوااسکریپت کلاینت | استخراج تابع از فایل واقعی و اجرا در Node | بازنویسی منطق، تستِ کدِ خودم است نه کدِ محصول |
| نحو | `token_get_all($src, TOKEN_PARSE)` | `php -l` در دسترس نیست |
| بستهٔ zip | `unzip -t` + `diff` فهرست دو نسخه | اثبات اینکه فقط فایل‌های قصدشده عوض شده‌اند |

**ادعای «رفع شد» در changelog، مدرک نیست.** تا اجرای کد آن را نشان ندهد،
باگ باز فرض می‌شود.
