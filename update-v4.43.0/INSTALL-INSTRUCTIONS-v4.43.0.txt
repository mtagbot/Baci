--------------------------------------------------------------------
علت دقیق مشکل (تشخیص کاربر — تایید شد)
--------------------------------------------------------------------
تگ <header> خودش کلاس `flex` دارد و فرزند مستقیم <body> است؛
بنابراین قانون قدیمی style.css:

    body > .flex { min-height:0; overflow:hidden; }

که برای «بدنه اصلی» (div.flex.flex-1) نوشته شده بود، هدر را هم
شامل می‌شد و هر چیزی که از لبه پایین هدر بیرون بزند — یعنی
پنجره کاربری — قیچی می‌شد.

--------------------------------------------------------------------
اصلاح در 4.43.0
--------------------------------------------------------------------
● فقط به خود هدر اضافه شد:
    header.navbar { overflow: visible !important; }
  → پنجره کاربری دیگر قیچی نمی‌شود.
● عمداً قانون کلی body > .flex تغییری نکرد، چون بدنه اصلی
  (سایدبار + main) به overflow:hidden نیاز دارد تا چیدمان
  «اپلیکیشن دسکتاپی» (اسکرول داخلی هر پنل) سالم بماند.
  بنابراین این تغییر هیچ عارضه جانبی روی اسکرول صفحات ندارد.
● سایر اصلاحات 4.42.0 حفظ شد: z-index هدر 2500، پنجره 6000،
  قواعد قطعی باز شدن (display:flex !important)، حالت موبایل
  تمام‌عرض زیر هدر.

--------------------------------------------------------------------
تست سریع:
--------------------------------------------------------------------
1) کلیک روی «کاربری» → پنجره زیر دکمه باز شود و «خروج» کلیک شود.
2) صفحه با جدول بلند → پنجره روی محتوا باشد، نه زیر آن و نه قیچی.
3) اسکرول داخلی صفحات (لیست دانش‌آموزان، منوی کناری) مثل قبل
   کار کند — تغییری نکرده است.
4) موبایل → دکمه 👤 → پنجره تمام‌عرض زیر هدر.
