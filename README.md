# Baci — سامانهٔ مدیریت مدرسهٔ SchoolDesk Pro

سایت (PHP + MySQL) و نرم‌افزار دسکتاپ ویندوز (SQLite) به‌همراه ربات‌های بله/تلگرام/روبیکا،
اسکنر حضور و غیاب، آزمون آنلاین، طراح زندهٔ آزمون، کارت و تگ QR، و گزارش‌های
Word/PDF.

**شاخهٔ جاری:** `arena/01a10d10-baci`
**نسخهٔ کد:** سایت **4.188.0** / دسکتاپ **2.112.0**

## اصلاحی پیشین: V4.184.0 — «گروه‌ها و کانال‌ها» و خروج از گروه از داخل سایت

پیش از این، تنها راهِ فهمیدن این‌که ربات در چه گروه‌هایی عضو است، پیدا کردن پیامش
در «پیام‌های دریافتی ربات» بود؛ خروج از گروه هم فقط از داخل خودِ بله/تلگرام ممکن
بود. حالا در همان صفحه، تب دوم **«گروه‌ها و کانال‌ها»** اضافه شده است:

- **فهرست همهٔ گفتگوها** — گروه، کانال و گفتگوی خصوصی — با نوع، شناسه/نام کاربری،
  وضعیت عضویت، زمان آخرین پیام، شمارش پیام‌ها و آخرین خطای API؛ با فیلتر نوع،
  فیلتر وضعیت و جستجو.
- **خروج از گروه با یک کلیک** (تأیید مرورگر + CSRF). هر مدیری که این صفحه را
  باز می‌کند می‌تواند خارج کند. خروج **برگشت‌ناپذیر** است؛ ردیف حذف نمی‌شود،
  وضعیت «خارج‌شده» می‌ماند و در «لاگ فعالیت» با عنوان «خروج ربات از گروه» ثبت
  می‌شود. برای گفتگوی خصوصی دکمه‌ای نیست.
- **افزودن دستی با شناسه** برای گروه‌های قدیمی‌تر که ربات پیش از این نسخه به آن‌ها
  اضافه شده و هنوز هیچ پیامی نفرستاده‌اند؛ شناسه با `getChat` اعتبارسنجی می‌شود.
- **بروزرسانی وضعیت** با `getChat` برای ۲۰ گفتگوی کهنه در هر کلیک (فقط مواردی که
  بیش از ۱۰ دقیقه بررسی نشده‌اند).

فهرست از همان چیزی ساخته می‌شود که ربات **دیده** است: هر پیام، هر دکمه، پیام
سرویسیِ افزودن/حذف عضو (هر دو پیام‌رسان) و `my_chat_member` (فقط تلگرام). هیچ APIای
«فهرست همهٔ گروه‌های ربات» را نمی‌دهد؛ پس گروهی که پیش از نصب این نسخه اضافه شده و
از آن پس هیچ پیامی نفرستاده، تا اولین پیام یا «افزودن دستی» دیده نمی‌شود — همین
محدودیت داخل صفحه هم نوشته شده است.

بدون تغییر دستی پایگاه‌داده: جدول `bot_chats` در اولین باز شدن صفحه خودش ساخته
می‌شود (هم MySQL و هم SQLite).

## اصلاحی پیشین: V4.183.0 — سه محور اصلاحی گزارش‌شده

۱) **وضعیت همگام‌سازی دیگر دروغ نمی‌گوید.**

   **الف) صفحهٔ وضعیت روی «در انتظار وضعیت همگام‌سازی» می‌ماند** در حالی که دکمهٔ
   «همگام‌سازی همین حالا» موفق بود. علت: ضربانِ سرویس پس‌زمینه تا تأیید صریح
   سرور معتبر شمرده نمی‌شد و چرخه‌های کامل نادرند (هر ۵ دقیقه یا پس از هر
   ویرایش)، پس در فاصلهٔ بین دو بررسی پنل به «در انتظار» برمی‌گشت. حالا هر
   تبادل موفق — چه چرخهٔ کامل و چه بررسی سبک — لحظهٔ تأیید را ثبت می‌کند و پنل
   از همان اثبات می‌خواند: **دستگاه بیکار ≠ دستگاه خراب**. هیچ قطعی، خطا یا
   تأخیر واقعی پوشانده نمی‌شود.

   **ب) بنر «invalid key» رفع شد.** سایت دو منبع کلید دارد و API به‌روزرسانی فقط
   یکی را می‌خواند؛ روی نصب‌هایی که با بستهٔ دسکتاپ جفت شده بودند، همگام‌سازی
   سالم بود و به‌روزرسانی «invalid key» می‌گرفت. حالا هر دو منبع خوانده می‌شود و
   در صورت تفاوت، پیام فارسی روشن («کلید به‌روزرسانی با کلید همگام‌سازی سایت
   یکسان نیست») با اطمینان‌بخشی این‌که داده‌های مدرسه طبق روال همگام می‌شوند
   نشان داده می‌شود — بدون بازگرداندن کلید در پاسخ.

۲) **«آماده‌سازی سوال جدید» در طراحی زندهٔ آزمون:** متن هر نوع سوال حالا
**راهنما (placeholder)** است و دیگر لازم نیست اول آن را پاک کنید؛ «بارم / نمره»
خالی می‌آید و ۱ فقط راهنماست؛ و تصویرِ داخل سوال یک **دکمهٔ ×** در گوشهٔ بالا
گرفت که تصویر را همان‌جا حذف و ذخیره می‌کند. متن‌های راهنما هرگز داخل سوال ذخیره
یا چاپ نمی‌شوند.

۳) **چاپ و PDF دقیقاً مثل طراحی زنده.** PDFی که ربات برای معاون اجرایی می‌فرستد
عرض کادر سوال را ۲۰۳mm و برگه‌های دوم/چهارم را ۸ میلی‌متر کوتاه‌تر می‌گرفت و
ارتفاع هر ردیف را هم بیشتر حساب می‌کرد؛ نتیجه: سوال‌هایی که در طراحی داخل یک
برگه جا می‌شدند در PDF به برگهٔ بعد می‌رفتند. هر سه عدد اکنون عیناً از همان CSS
طراحی زنده می‌آید (۲۱۰mm، ۲۵۷mm فرد / ۲۹۴mm زوج) و ویرایشگر دست‌نخورده ماند.

## تست‌ها

۶۱ سوئیت با اجرای **واقعی** PHP (php-wasm 8.3 + SQLite) — نه بازنویسی منطق در تست:

```sh
npm ci --prefix tests
unzip -qo Release_V1.1-Site.zip -d /tmp/baci-site
SITE=/tmp/baci-site PATCH=update-v4.152.0 bash scripts/run-tests.sh
```

> سورس تست باید توزیع **سایت** باشد. با سورس دسکتاپ دو سوئیت به‌طور محیطی قرمز
> می‌شوند — جزئیات در بند ۷ `docs/BRANCH-TIMELINE-FA.md`.

بازسازی `Release_V1.1` از صفر:

```sh
python3 -m pip install --target .cache/release-v1/compiler ziglang==0.14.1
python3 scripts/build-full-release.py --stage-only
node tests/test-full-release-install.mjs        # نصب تازه، ۵۸ assertion
python3 scripts/build-full-release.py
python3 tests/test-full-release-packaging.py    # ۱۱ تست بسته‌بندی
```

جزئیات در [release-v1.0/BUILD.md](release-v1.0/BUILD.md).
