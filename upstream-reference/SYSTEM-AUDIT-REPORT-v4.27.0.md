# گزارش بررسی اجمالی سیستم — v4.27.0

## نتیجه کلی

بررسی ایستا و معماری روی فایل‌های فعلی پروژه انجام شد. از نظر ساختار کلی، پروژه اکنون شامل ماژول‌های اصلی موردنیاز مدرسه است:

- مدیریت دانش‌آموزان
- مدیریت دبیران و نقش‌ها
- مدیریت کلاس‌ها، دروس و برنامه هفتگی
- کارنامه‌ها، چاپ، تحلیل و ارسال رباتی
- موارد انضباطی و پنل معاون/ناظم
- پنل مشاور
- پنل معاون اجرایی
- ربات بله و تلگرام
- امتحانات، صندلی، کارت صندلی، طراحی زنده آزمون، بانک سوالات
- گزارش‌گیری‌ها
- تنظیمات، فونت‌ها، ظاهر، پیامک و اعلان‌ها

در بررسی ایستا، مسیرهای PHP ارجاع‌شده در `href/action/src` بررسی شدند و ارجاع گم‌شده‌ای پیدا نشد. همچنین CDNهای فونت/اسکریپت خارجی و استفاده از `eval` یا `new Function` در فایل‌های پروژه دیده نشد.

> نکته مهم: در محیط فعلی ابزار `php` نصب نیست، بنابراین lint واقعی PHP با `php -l` و تست اجرایی سمت سرور انجام‌پذیر نبود. موارد زیر بر اساس تحلیل فایل‌ها، مسیرها و ساختار پروژه است. برای تایید نهایی production، اجرای smoke test روی هاست واقعی با PHP/MySQL ضروری است.

### ارزیابی معماری دیتابیس

   - `students(national_id, academic_year)`
   - `students(class_name, grade_level, academic_year)`
   - `reports(student_id, academic_year, report_month)`
   - `report_grades(report_id, subject_name)`
   - `student_discipline_records(student_id, review_status, is_justified)`
   - `exam_schedules(academic_year, exam_month, class_name, subject_name)`
   - `exam_designs(exam_id)`

2. اگر تعداد سال‌های تحصیلی و دانش‌آموزان زیاد شود، بهتر است به‌جای کپی رکورد کامل دانش‌آموز برای هر سال، یک جدول enrollment جداگانه اضافه شود:
   - `student_enrollments(student_id, academic_year, grade_level, class_name, status)`

   اما در معماری فعلی که رکورد دانش‌آموز بر اساس سال کپی/به‌روزرسانی می‌شود، سیستم قابل اجراست.

### نکته runtime مهم

برای تبدیل PDF به تصویر، یکی از این‌ها باید فعال باشد:

- Imagick با policy مجاز برای PDF
- Ghostscript قابل اجرا با `exec`

اگر هاست policy PDF را در ImageMagick بسته باشد، حتی با نصب Imagick تبدیل PDF انجام نمی‌شود. در این حالت باید policy ImageMagick اصلاح شود یا Ghostscript فعال باشد.

## وضعیت پیامک ملی پیامک

### پیاده‌سازی فعلی

در `sms-panel.php`:

- provider `melipayamak` با SOAP پیاده‌سازی شده است.
- endpoint:
  - `http://api.payamak-panel.com/post/send.asmx?wsdl`
- متد:
  - `SendSimpleSMS2`

### نیازهای runtime

برای ارسال واقعی:

1. افزونه PHP SOAP باید فعال باشد.
2. در تنظیمات وارد شود:
   - provider = `melipayamak`
   - username
   - password
   - sender number
3. خط ارسال باید از سمت ملی پیامک اجازه ارسال داشته باشد.

## جمع‌بندی نهایی

از نظر بررسی ایستا، پروژه به سطح قابل قبولی از کامل بودن رسیده و مسیرهای اصلی، فایل‌های کلیدی، دیتابیس و ماژول‌ها وجود دارند. نشانه‌ای از لینک PHP گم‌شده، CDN خارجی یا استفاده از eval در فایل‌های پروژه پیدا نشد.

برای اعلام آمادگی production، توصیه می‌شود روی سرور واقعی یک مرحله smoke test انجام شود. اگر تست‌های runtime بالا با موفقیت انجام شوند، پروژه برای بهره‌برداری عملیاتی آماده است.
