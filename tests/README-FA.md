# تست‌ها — اجرای کد واقعی، نه ادعا

> **قاعده:** هیچ باگی «رفع شده» حساب نمی‌شود مگر اینکه اجرای کد نشان دهد.
> changelog مدرک نیست.

## یک دستور برای همه‌چیز

```bash
bash scripts/run-tests.sh
```

بار اول `npm install` خودش اجرا می‌شود. بعد از آن هر اجرا چند ثانیه است.

## چهار سوئیت

| سوئیت | فایل | چه می‌سنجد |
|---|---|---|
| بررسی نحوی | `lint.mjs` | هر ۱۲۴ فایل PHP سایت با `token_get_all(…, TOKEN_PARSE)` |
| منطق تایمر | `test-timer.mjs` | `startTimer()` استخراج‌شده از فایل واقعی — ۱۸ بررسی |
| انتخاب گزینه | `test-save.mjs` | `saveAnswer()` استخراج‌شده از فایل واقعی — ۱۳ بررسی |
| راندن کامل آزمون | `verify.mjs` | سایت واقعی روی PHP + SQLite — ۳۵ بررسی |

## چرا php-wasm؟

در محیط توسعه باینری PHP و `php -l` وجود ندارد. `@php-wasm/node` نسخهٔ واقعی
PHP 8.3 با `pdo_sqlite` را در Node اجرا می‌کند، پس کد **واقعاً** اجرا می‌شود.

## چرا توابع جاوااسکریپتی «استخراج» می‌شوند؟

چون بازنویسیِ منطق، تستِ کدِ خودم است نه کدِ محصول. `test-timer.mjs` و
`test-save.mjs` متن تابع را با تطبیق آکولاد از `online-exam-take.php` بیرون
می‌کشند و فقط `document` و `fetch` را stub می‌کنند. تگ‌های `<?php echo … ?>`
داخل جاوااسکریپت با مقدار رندرشده جایگزین می‌شوند — همان چیزی که مرورگر
دانش‌آموز می‌بیند.

## استفاده‌های دیگر

**تست یک وصله قبل از بسته‌بندی:**
```bash
PATCH=update-v4.127.0 bash scripts/run-tests.sh
```

**تست یک سورس دیگر:**
```bash
SITE=.arena/current/SchoolDeskPro/www bash scripts/run-tests.sh
```
اگر `SITE` ست نشود، هارنس به‌ترتیب می‌گردد: `.arena/current/SchoolDeskPro/www`،
سپس جدیدترین `SchoolDeskPro-v*-win64.zip` در ریشهٔ ریپو (خودکار استخراج می‌شود).

**فقط یک سوئیت:**
```bash
cd tests && node verify.mjs
```

## چهار نکتهٔ حیاتی هارنس (با آزمون و خطا به دست آمده)

۱. `ini_set`/`session_name`/`session_id`/`session_start` باید **قبل از هر echo**
   اجرا شوند، وگرنه `session_start()` خود سایت خطا می‌دهد و هر صفحه به صفحهٔ
   ورود redirect می‌شود.

۲. `echo " "` بعد از session → `headers_sent()` راست می‌شود → `redirect()` به‌جای
   `header()` مقصد را echo می‌کند. در SAPI خط فرمان `header()` بی‌اثر است، پس این
   **تنها** راه گرفتن مقصد redirect است.

۳. شناسهٔ نشست فقط `[A-Za-z0-9-,]` — زیرخط (`_`) رد می‌شود.

۴. `require_once` برای `includes/functions.php` و `includes/db.php`؛ با `require`
   معمولی کلاس `SQLitePDO` دوباره declare می‌شود و fatal می‌دهد.

## یافته‌های جانبی که این تست‌ها بیرون دادند

**`export-excel.php` به `short_open_tag=Off` وابسته است.** این فایل در بخش HTML
خود پردازشگر خام `<?mso-application progid="Excel.Sheet"?>` دارد. بستهٔ دسکتاپ
در `php/php.ini` صریحاً `short_open_tag = Off` دارد، پس آنجا سالم است؛ ولی روی
میزبانی‌ای که این تنظیم `On` باشد، **fatal parse error** می‌گیرد و خروجی اکسل
کاملاً از کار می‌افتد. `lint.mjs` این را به‌عنوان هشدار قابلیت حمل گزارش می‌دهد.

> `short_open_tag` از نوع `PHP_INI_PERDIR` است، پس با `ini_set` در زمان اجرا
> عوض نمی‌شود. به همین دلیل lint همان معنای `Off` را بازسازی می‌کند.

## اسکنر برگشت‌پذیر (اصلاح همان نسخه 4.152.0)

دو سوئیت `test-scanner-lifecycle.mjs` و `test-scanner-page.mjs` به اجرای کلی اضافه شده‌اند (اکنون ۲۱ مجموعه). اولی کنترلر واقعی با دوربین/زمان‌بندی شبیه‌سازی‌شده را بدون شبکه یا دیتابیس اجرا می‌کند؛ دومی احراز هویت و هر دو مسیر نسخه قدیمی را با PHP و داده آزمایشی می‌سنجد. متغیر اختیاری `SCANNER_JS` مسیر کنترلر را برای کنترل منفی تعیین می‌کند؛ فایل پیش‌فرض، سورس انتشار جدید است.

آزمون اختیاری `test-scanner-browser.mjs` به HTML تولیدشده توسط `test-scanner-page.mjs` و بسته‌های آزمایشی `playwright`, `@sparticuz/chromium`, `acorn` نیاز دارد. با `BROWSER_MODULES` مسیر آن‌ها تعیین می‌شود. در محیط فعلی:

```bash
SITE=.cache/desktop/SchoolDeskPro/www PATCH=update-v4.152.0 node tests/test-scanner-page.mjs
LD_LIBRARY_PATH=.cache/chrome-libs/lib node tests/test-scanner-browser.mjs
python3 scripts/release-scanner.py
python3 tests/test-scanner-packaging.py
```

۲۰ نمونه QR روی ویدئوی مصنوعی، کتابخانه واقعی و XHR اجرا می‌شوند؛ نصف موارد Worker واقعی دارند و نصف دیگر مسیر سازگاری با CPU کندشده و قابلیت‌های جدید غیرفعال. آزمون مرورگر فیزیکی موبایل نیست. شرح دقیق دامنه/بازگشت در `docs/RELEASE-scanner-v4.152.0-FA.md` است.

برای سنجش سرعت اسکنر، `BENCH_REPEATS=3` هر ۱۰ حالت را سه بار در هر مسیر تکرار می‌کند؛ `BENCH_REPORT` خروجی خام زمان تشخیص/سرور را ذخیره می‌کند. `SCANNER_JS` مسیر کنترلرِ نسخه مبنا را هم در آزمون مرورگر تعیین می‌کند. دو نسخه را پشت‌سرهم روی یک محیط اجرا کنید. `SCANNER_SERVER_DELAY=250` تأخیر مصنوعی API را برای تفکیک زمان خواندن و تأیید اضافه می‌کند. مقایسه ثبت‌شده با e6b2684 در `docs/scanner-speed-benchmark.json` است؛ این اعداد معیار گوشی فیزیکی نیستند.

برای اصلاح فوکوس نزدیک `camera3`، سوئیت کنترلر اکنون ۶۶ مورد دارد و بازخوانی واقعیِ شبیه‌سازی‌شده تنظیمات، عدم انطباق/رد/تأخیر، بازگردانی ناموفق، قفل به مقدار زمان گرفتن فریم، نوردهی جبران‌شده، محافظ تاریکی/سفیدی و چراغ را پوشش می‌دهد. `OPTICS_TEST=1 SCANNER_MOTION_FIXTURES=1` در آزمون مرورگر، درایور تنظیمات ساختگی و چهار حالت حرکت/تاری خفیف را به هر مسیر اضافه می‌کند (مجموع ۲۸ نمونه). این آزمون **فوکوس یا شاتر دوربین فیزیکی را اندازه نمی‌گیرد**؛ هدف کنترل رفتار برنامه و حفظ خوانایی نمونه‌های تصویری است. راهنمای انتشار اسکنر این محدودیت و روش آزمایش واقعی را توضیح می‌دهد.

## به‌روزرسانی آنلاین دسکتاپ (اصلاح همان 4.152.0 / 2.83.0)

سوئیت `test-desk-update.mjs` به اجرای کلی اضافه شد (اکنون ۳۲ مجموعه). این سوئیت کد واقعی PHP را اجرا می‌کند: ساخت بستهٔ ZIP در جاوااسکریپت/PHP، اعتبارسنجی مسیر و نوع فایل، بررسی PE فایل اجرایی، چک‌سام سراسری و فهرست فایل‌ها، نصب واقعی روی ریشهٔ وب با پشتیبان‌گیری، وضعیت/آماده‌بودن، فروشگاه سمت سایت، و endpoint `desk-update-api.php` (کلید درست/نادرست/خالی، GET، دانلود، شناسهٔ ناایمن) و گیت تب‌های «تنظیمات دیگر» بین توزیع سایت و دسکتاپ.

```bash
PATCH=update-v4.152.0 node tests/test-desk-update.mjs
python3 tests/test-desk-update-packaging.py
python3 scripts/release-desk-update.py
```

`test-desk-update-packaging.py` مسیرهای محرمانه/اجرایی، یکسانی بایت‌به‌بایت دو نسخهٔ `desk_update_zip.php` و PE بودن `SchoolDeskPro.exe` را کنترل می‌کند. شرح کامل و محدودیت‌ها در `docs/DESKTOP-ONLINE-UPDATE-FA.md` است.

## تکرار متوالی تگ و کارت — اصلاح همان 4.152.0 / 2.83.0

`test-print-copies.mjs` به دستور جمعی اضافه شده است؛ `scripts/run-tests.sh` اکنون **۲۲ سوئیت** اجرا می‌کند. این آزمون **۶۳ حالت PHP/SQLite** را با فایل‌های واقعی چاپ بررسی می‌کند: عدد ۱–۱۰ و نامعتبرها، ترتیب متوالی هر دانش‌آموز، تمام sortها و فیلترها، QR مشترک، تکی/روی‌وپشت، تعداد صفحات و سال/وضعیت دانش‌آموز. جابه‌جاکردن حلقهٔ نسخه و دانش‌آموز عمداً تست را قرمز می‌کند.

```bash
SITE=.cache/desktop/SchoolDeskPro/www PATCH=update-v4.152.0 node tests/test-print-copies.mjs
# اختیاری: همان وابستگی‌های مرورگر تست اسکنر (Playwright / @sparticuz/chromium / acorn)
SITE=.cache/desktop/SchoolDeskPro/www PATCH=update-v4.152.0 PRINT_BROWSER=1 \
  LD_LIBRARY_PATH="$PWD/.cache/chrome-libs/lib" node tests/test-print-copies.mjs
python3 tests/test-print-copies-packaging.py
```

حالت مرورگر **۴۴ بررسی** دارد: ذخیره/بازنشانی، انتقال عدد در لینک‌های چاپ تکی و گروهی، پیش‌نمایش واقعی اولین صفحه و محدودبودن DOM حتی برای ۲۰۳ دانش‌آموز، و decode واقعی **۱۱۷ QR** چاپ سه و ده نسخه. PDFها و تصویر پیش‌نمایش در `.cache/print-copies` ذخیره می‌شوند. چهار PDF با `pypdf` نیز از نظر تعداد صفحات بررسی شدند؛ تست چاپگر فیزیکی انجام نشده است. بسته‌بندی چهار آزمون مستقل دارد و دقیقاً دو فایل PHP مجازند.

جزئیات و نتیجهٔ نهایی: [`docs/RELEASE-print-copies-v4.152.0-FA.md`](../docs/RELEASE-print-copies-v4.152.0-FA.md).

## گردش‌کار دبیر و برنامهٔ هفتگی — ۲۰۲۶-۰۹-۱۶

مجموعهٔ جمعی اکنون **۲۳ سوئیت** دارد. `test-staff-workflows.mjs` با **۴۴ بررسی PHP/SQLite واقعی در حافظه**، عدم تخریب داده در خطای میانی، حفظ شناسه و ستون جانبی، تعارض نسخه، نیم‌زنگ، نام دبیر واردشده، سال/دسترسی/CSRF، محدودیت یک آزمون برای دبیر/سال/کلاس/درس، حفظ تکراری‌های قدیمی و دامنهٔ چاپ پایه‌ای را می‌سنجد.

```bash
SITE=.cache/desktop/SchoolDeskPro/www PATCH=update-v4.152.0 node tests/test-staff-workflows.mjs
# همان وابستگی‌های اختیاری مرورگر تست اسکنر:
SITE=.cache/desktop/SchoolDeskPro/www PATCH=update-v4.152.0 STAFF_BROWSER=1 \
  LD_LIBRARY_PATH="$PWD/.cache/chrome-libs/lib" node tests/test-staff-workflows.mjs
python3 tests/test-staff-packaging.py
```

حالت مرورگر، اسکریپت عمومی searchable-select واقعی را بار می‌کند تا بازگشت باگ فیلد اضافه پنهان نماند. انتخاب مکرر درس/دبیر، نیم‌زنگ، تأیید/لغو پاک‌کردن، درخواست کند و ویرایش بعدی، قطع شبکه/تلاش دوباره و بازیابی پس از reload آزموده می‌شوند. بازگشت از پنجرهٔ ساخت، دکمهٔ ساخت را با انتخاب/ویرایش جایگزین می‌کند؛ مقصد طراحی در این آزمون ناوبری شبیه‌سازی شده، اما محدودهٔ دادهٔ `exam-print.php` جداگانه با PHP واقعی تست می‌شود. PDF واقعی لیست دبیر نیز در `.cache/staff` تولید می‌شود.

سه آزمون بسته‌بندی شامل نگهبان دقیق «فقط عبارت سلول PDF تغییر کند، نه Word» است. بستهٔ قدیمی گزارش بدون بازسازی نگه داشته شده و با هش تاریخی آزموده می‌شود. کنترل منفیِ حذف `data-no-search` باید در مرورگر به کنترل اضافه و شکست تست برسد. MySQL اجرایی، چاپگر فیزیکی و همهٔ مرورگرهای قدیمی تست نشده‌اند.
