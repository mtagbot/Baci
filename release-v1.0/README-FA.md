# Release_V1.0 — نصب کامل سایت و دسکتاپ

این انتشار **کامل و مستقل** است؛ نصب نسخهٔ پایه یا وصله‌های قبلی لازم نیست. تغییرات سایت تا **4.152.0** و دسکتاپ تا **2.83.0**، از جمله اصلاحات اخیر آزمون کلاسی/پایه، برنامهٔ دبیران، ورود و نشست‌ها، کارت سفارشی و لوگو، اسکنر و خروجی‌های چاپ/Word، به‌صورت تجمیعی قرار گرفته‌اند. نام انتشار Release_V1.0 است؛ شماره‌های داخلی برنامه عوض نشده‌اند.

**فقط برای نصب از صفر.** این ZIPها را روی مدرسهٔ فعال یا پوشهٔ نسخهٔ قبلی استخراج نکنید. برای ارتقای نسخهٔ فعال، ابتدا پشتیبان مستقل بگیرید و از مسیر ارتقا/وصله‌های مربوط به همان نصب استفاده کنید.

## بازسازی ۱۹ سپتامبر ۲۰۲۶ — همهٔ اصلاحی‌های منتشرشده از پیش داخل بسته است

این بازسازی همان اصلاحی‌هایی را که پیش‌تر به‌صورت زنجیره‌ای نصب می‌شدند، **از پیش درون خود دارد**؛
پس نصب از صفر به هیچ بستهٔ اصلاحی جداگانه‌ای نیاز ندارد. اصلاحی‌های تجمیع‌شده (به ترتیب نصب):

`svg-responsive` → `student-workflow` → `preview-navigation` → `fast-ui` → `mobile-hubs` →
`report-tools` → `settings-health` → (دسکتاپ: `reports-layout`) → `bot-outbox` →
(دسکتاپ: `optimized-sync` → `event-sync`) → `recovery-ui`

شمارهٔ داخلی سایت (4.152.0) و دسکتاپ (2.83.0) عوض نشده است. فهرست دقیق این بسته‌ها و منبع هر فایل
در `RELEASE-MANIFEST.json` (کلید `correctives`) و در `scripts/build-full-release.py` ثبت شده است.

**دسکتاپ — نخستین اجرا:** فایل اجرایی بازسازی‌شده، پوشهٔ وب را یک‌بار از `www` به `reports` تغییر
نام می‌دهد (با قفل، اعتبارسنجی و بازگردانی؛ طبق اصلاحی `reports-layout`). پس از آن نشانی برنامه
`http://127.0.0.1:PORT/reports/` است و **پشتیبان‌گیری شما باید از `reports/` انجام شود، نه `www/`.**
اگر هر دو پوشه با هم دیده شوند، برنامه برای حفظ اطلاعات متوقف می‌شود؛ پوشه‌ها را کورکورانه حذف نکنید.

## اصلاحات ادغام‌شده در بازسازی ۱۷ سپتامبر ۲۰۲۶

علاوه بر اصلاحات قبلی، این بازسازی شامل ورود اول بدون کپچا و الزام آن پس از خطای رمز، قلم مشترک رابط/کارنامه و جاسازی TTF در PDF، چهار رنگ قابل‌تنظیم، QR مربعی بزرگ‌تر، هر دو سرستون نام دبیر، حذف صفحهٔ سوم سفید، حاشیهٔ امن حدود ۶ میلی‌متر در فهرست‌های چاپی، حذف ردیف تکراری کلاس مستثنا و پیام ویرایشگر با نام واقعی کلاس‌ها است.

- Word دبیر دست‌نخورده است. فهرست مدرسه همچنان تک‌صفحه، با هر دو چیدمان و A4/A3 افقی است؛ برای حاشیهٔ امن، در صورت نیاز اندازهٔ نام‌ها طبق اولویت تک‌صفحه بودن از هدف ۸ پوینت کمتر می‌شود.
- برای همسانی PDF/تصویر، TTF محلی انتخاب کنید. WOFF/WOFF2 و قلم سیستمی از مسیر PDF مرورگر استفاده می‌کنند؛ تصویر سرور به TTF همان قلم و GD دارای FreeType واقعی نیاز دارد. Excel قلم را جاسازی نمی‌کند و قلم باید روی دستگاه مقصد نصب باشد.
- کش تبدیل PDF در `backups/font-cache` است؛ این پوشه باید برای PHP قابل‌نوشتن و برای وب غیرقابل‌دسترسی باشد.
- سقف خطای ورود مستقل از کپچا است؛ پاک‌کردن کوکی محدودیت پایدار IP را صفر نمی‌کند.
- این بازسازی با PHP WebAssembly و Chromium آزمایش شده است. جزئیات و حدود آزمون، از جمله نبود تأیید بومی Word/ویندوز/چاپگر و GD FreeType در محیط آزمایش، در [راهنمای اصلاحات](https://github.com/mtagbot/Baci/blob/arena/01a0a1d9-baci/CORRECTIONS-UI-PRINT-FA.md) آمده است. آزمون MySQL ذکرشده در بخش نصب مربوط به زیرساخت انتشار قبلی است؛ در این بازسازی دوباره اجرا نشده است.

## کدام فایل؟

- `Release_V1.0-Site.zip`: محتوای ریشهٔ سایت PHP؛ برای هاست و MySQL.
- `Release_V1.0-Desktop.zip`: پوشهٔ کامل `SchoolDeskPro`، شامل اجراکنندهٔ ویندوز، PHP قابل‌حمل، سایت داخلی و SQLite؛ نیازی به XAMPP یا MySQL محلی ندارد.
- `Release_V1.0-SHA256SUMS.txt`: برای کنترل سلامت دانلود.

بسته‌ها **فاقد حساب و رمز پیش‌فرض، دانش‌آموز، دبیر، کلاس، نمره، آزمون، نشست مرورگر و کلید همگام‌سازی یک مدرسهٔ قبلی** هستند. قالب‌های آمادهٔ پیام ربات، تنظیمات ساختاری و فونت‌های همراه، دادهٔ نمونهٔ مدرسه نیستند. مدیر، نام مدرسه و سال تحصیلی هنگام نصب مشخص می‌شوند.

## نصب سایت از صفر

1. هاست با **PHP 8.1 یا بالاتر** و MySQL تهیه کنید. برای میزبانی اینترنتی، شاخهٔ PHP تحت پشتیبانی و MySQL پشتیبانی‌شدهٔ ارائه‌دهندهٔ هاست را انتخاب کنید. نصب واقعی با PHP 8.3.33 (WebAssembly) و MySQL 5.7.29 در محیط آزمایش بررسی شده است؛ MySQL 8.x مستقلاً در این محیط آزمایش نشده. MySQL 5.7 منقضی است و صرفاً محیط آزمون سازگاری بود، نه پیشنهاد برای میزبانی تازه.
2. افزونه‌های `pdo_mysql`, `mbstring`, `gd`, `curl`, `openssl`, `fileinfo`, `zip`, `zlib`, `dom` لازم‌اند. `PDO` و نشست PHP نیز باید فعال باشند. حافظهٔ ۲۵۶ مگابایت یا بیشتر و برای خروجی‌های بزرگ ۵۱۲ مگابایت پیشنهاد می‌شود.
3. دامنه و **HTTPS** را فعال کنید. محتوای ZIP سایت را در یک پوشهٔ خالی هاست، مثلاً ریشهٔ دامنه یا زیرپوشهٔ `school`، استخراج کنید؛ نه خود فایل ZIP را به‌عنوان سایت.
4. در پنل هاست یک دیتابیس **کاملاً خالی** و یک کاربر مخصوص آن بسازید. کاربر باید مجوزهای ساخت/تغییر جدول، شاخص و خواندن/نوشتن را داشته باشد. برای همگام‌سازی با دسکتاپ، مجوز `TRIGGER` هم لازم است. اطلاعات اتصال را فقط داخل نصب‌یار خودتان وارد کنید.
5. مسیرهای `config`, `uploads`, `backups` باید برای PHP قابل‌نوشتن باشند. مجوز مناسب مالک فایل/هاست را تنظیم کنید؛ دسترسی عمومی `777` توصیه نمی‌شود.
6. برای جلوگیری از تصاحب نصب توسط بازدیدکنندهٔ ناشناس، در مدیر فایل هاست، `config/install-access.example.php` را با نام `config/install-access.php` کپی کنید. مقدار `return '';` را با عبارت محرمانهٔ تصادفی حداقل ۳۲ نویسه‌ای خودتان پر کنید. مثال فایل، **کلید آماده ندارد**. برای تولید مقدار از مدیر رمز استفاده کنید؛ آن را در چت یا مخزن منتشر نکنید.
7. نشانی `https://YOUR-DOMAIN/installer.php` را باز کنید؛ در نصب زیرپوشه، نام زیرپوشه را هم بیاورید. کلید اجازهٔ نصب، مشخصات MySQL، نام مدرسه، سال تحصیلی و اطلاعات مدیر کل را وارد کنید. نام کاربری انگلیسی و رمز مستقل حداقل ۱۲ نویسهٔ انگلیسی تعیین کنید.
8. همهٔ بررسی‌های پیش‌نیاز باید سبز شوند. نصب‌یار خودش جدول‌های پایه و تغییرات ساختاری نسخه‌های جدید را اجرا می‌کند؛ **فایل SQL را دستی import نکنید**.
9. پس از پیام موفقیت، از `admin-login.php` با اطلاعات انتخابی خودتان وارد شوید. `installer.php` و `config/install-access.php` را از هاست حذف کنید. فایل‌های `config/database.php`، `config/installed.lock` و `config/desk-sync-key.php` را نگه دارید و همراه پشتیبان محرمانه ذخیره کنید.

### تنظیم وب‌سرور

Apache/LiteSpeed باید `.htaccess` را اجرا کند. پوشه‌های `config`, `includes`, `sql`, `vendor`, `backups` نباید مستقیماً از وب قابل‌خواندن باشند. داخل `uploads` اجرای PHP/اسکریپت ممنوع است. پس از نصب بررسی کنید درخواست `config/installed.lock`، `sql/schema-sqlite.sql` و `backups/` پاسخ 403 یا 404 بگیرد.

در **Nginx**، `.htaccess` اثری ندارد؛ مدیر سرور باید قواعد معادل را **قبل از location عمومی PHP** اضافه کند (پیشوند را با زیرپوشهٔ واقعی سایت تطبیق دهد):

```nginx
location ~ ^/(config|includes|sql|vendor|backups)(/|$) { deny all; }
location ~ /\. { deny all; }
location ~* ^/uploads/.*\.(php[0-9]?|phtml|phar|cgi|pl|py|sh)(/|$) { deny all; }
location ~* \.(sqlite(3|-wal|-shm)?|db|sql|ini|log|bak|backup|env|lock|py|md|json)$ { deny all; }
```

این قطعه جایگزین پیکربندی کامل PHP-FPM و TLS نیست. در میزبانی زیرپوشه، مثلاً `/school`، الگوی دو قاعدهٔ مسیرمحور باید با `/school/` شروع شود.

## نصب دسکتاپ از صفر

1. ZIP دسکتاپ را **کامل** در پوشهٔ خالی و قابل‌نوشتن روی ویندوز ۶۴ بیتی استخراج کنید؛ مثلاً `C:\SchoolDeskPro-Release1`. از اجرای EXE مستقیم داخل ZIP، مسیر فقط‌خواندنی، `Program Files` و پوشهٔ مدرسهٔ قبلی خودداری کنید.
2. Microsoft Edge یا Google Chrome نصب باشد. در بعضی نصب‌ها WebView2 موجود نیز شناسایی می‌شود. اگر Windows نبودِ DLLهای Visual C++ را گزارش داد، **Microsoft Visual C++ Redistributable 2015–2022 x64** را از وب‌سایت رسمی Microsoft نصب کنید؛ DLL ناشناس دانلود نکنید.
3. `SchoolDeskPro.exe` را اجرا کنید. در نخستین اجرا نصب‌یار محلی باز می‌شود؛ مشخصات مدرسه و مدیر را تعیین کنید. دیتابیس خالی SQLite داخل `SchoolDeskPro/data/school.sqlite` ساخته می‌شود. نیازی به کلید اجازهٔ نصب هاست یا مشخصات MySQL نیست.
4. با حساب ساخته‌شده وارد شوید. سرویس داخلی فقط برای همان رایانه روی loopback اجرا می‌شود؛ برای استفادهٔ شبکه‌ای آن را روی اینترنت باز نکنید.
5. برای پشتیبان کامل، برنامه را ببندید و **کل پوشهٔ SchoolDeskPro** را کپی کنید. داده‌های واقعی در `data` و فایل‌های بارگذاری‌شده در `www/uploads` هستند؛ تنظیمات محرمانهٔ `www/config` را هم نگه دارید. پوشه را با کاربران غیرمجاز به اشتراک نگذارید.

PHP قابل‌حمل ویندوز همان **8.1.34 x64** بستهٔ اصلی پروژه است و برای سازگاری تعویض نشده؛ این شاخه در زمان انتشار دیگر تحت پشتیبانی امنیتی PHP نیست. آن را سرویس عمومی نکنید. محیط ویندوز بومی در محیط ساخت این انتشار در دسترس نبوده؛ اجرای EXE و چرخهٔ پنجره/مرورگر باید روی رایانهٔ مقصد کنترل شود.

## اتصال دسکتاپ به سایت

- هر نصب سایت هنگام نصب کلید تصادفی و متفاوت خودش را می‌سازد؛ **کلید مشترک قدیمی در این بسته‌ها وجود ندارد**.
- مدیر کل سایت به «همگام‌سازی با سایت» برود و کلید همان نصب را دریافت کند.
- در دسکتاپ، نشانی HTTPS فایل `desk-sync-api.php` همان سایت و کلید را در تنظیمات همگام‌سازی وارد کنید. مسیر جدید آزمون‌های کلاسی هم از همان کلید استفاده می‌کند.
- اتصال در بستهٔ تازه **پیکربندی نشده** است؛ تا زمانی که خودتان نشانی و کلید را وارد نکنید به مدرسهٔ دیگری متصل نمی‌شود.
- **پیش از اولین اتصال از هر دو طرف پشتیبان بگیرید.** دریافت اولیهٔ سایت می‌تواند داده‌های محلی را جایگزین کند؛ ابتدا سایت مدرسه را آماده کنید و سپس دسکتاپ خالی را به همان مدرسه وصل کنید.
- کلید دسترسی گسترده به اطلاعات مدرسه می‌دهد؛ فقط در رایانه‌های مورد اعتماد قرار گیرد. برای باطل‌سازی، مقدار `config/desk-sync-key.php` سایت را با ۶۴ نویسهٔ هگز تصادفی جدید عوض و دستگاه‌های مجاز را دوباره تنظیم کنید.

## کنترل‌های بعد از نصب

- صفحهٔ ورود مدیر و نقش‌های دانش‌آموز/دبیر؛ تغییر مشخصات مدرسه و سال تحصیلی.
- ساخت یک کلاس، یک دانش‌آموز آزمایشی خودتان و یک درس/دبیر؛ سپس حذف دادهٔ آزمایشی خودتان.
- برنامهٔ هفتگی و پنجشنبه طبق برنامهٔ واقعی؛ آزمون کلاسی و گروه پایه، کپی/طرح تازه و مستثنی‌کردن عضو.
- کارت سفارشی، محل لوگو قبل از نام مدرسه، بارگذاری/بازنشانی لوگو و متن دستی پایین کارت؛ قالب‌های قدیمی باقی هستند.
- خروجی Word و چاپ A4/A3؛ نام فارسی و اندازهٔ فونت در رایانه/چاپگر مقصد کنترل شود. در چاپ کارت، مقیاس ۱۰۰٪، یک صفحه در هر برگ و بدون سربرگ/پابرگ مرورگر.
- اسکنر دوربین نیازمند HTTPS در سایت، مجوز دوربین و مرورگر سازگار است. قفل فوکوس نزدیک فقط در صورت پشتیبانی سخت‌افزار اعمال می‌شود؛ اسکنر قدیمی برای بازگشت حفظ شده است.
- ربات، پیامک و ارتباط اینترنتی نیازمند حساب/کلید واقعی خودتان هستند. تحلیل خودکار PDF منبع آزمون، اگر استفاده شود، علاوه بر PHP به Python و کتابخانه‌های همان اسکریپت احتیاج دارد؛ برای این قابلیت Python 3 و `PyMuPDF` و `python-bidi` لازم‌اند؛ `Pillow` اختیاری است. نصب: `python -m pip install PyMuPDF python-bidi Pillow`. راهنمای فنی داخل `analyze_exam_pdf.py` را بخوانید. این وابستگی اختیاری در PHP ویندوز جاسازی نشده است.

## خطا یا نصب ناقص

نصب‌یار خطا را موفقیت تلقی نمی‌کند و اتصال خراب MySQL را به SQLite تبدیل نمی‌کند. روی دیتابیس دارای جدول یا فایل تنظیمات موجود نصب نمی‌شود. اگر عملیات در میانه قطع شد، MySQL ممکن است برخی جدول‌های خالی را ساخته باشد؛ به دلیل رفتار DDL، بازگشت کامل تراکنشی تضمین نمی‌شود. آن دیتابیس/پوشه را برای بررسی نگه دارید و با بانک/پوشهٔ خالی جدید دوباره نصب کنید. هیچ جدول قبلی خودکار حذف نمی‌شود.

پارامتر `force=1` یا حذف کوکی، نصب دوباره/بازنشانی رمز را فعال نمی‌کند. حتی حذف فقط `installed.lock` کافی نیست. برای فراموشی رمز، فایل‌های قفل و دیتابیس را پاک نکنید؛ از بازیابی مدیریتی و پشتیبان استفاده کنید.

اجراکنندهٔ بازسازی‌شده امضای دیجیتال ندارد؛ پیش از اجرا منبع دانلود و SHA256 بسته را کنترل کنید.

تبدیل صفحات PDF منبع به تصویر در سرور، در مسیرهایی که از تبدیل سمت سرور استفاده می‌کنند، به Imagick با پشتیبانی PDF/Ghostscript یا ابزارهای متناظر نصب‌شدهٔ سیستم نیاز دارد. این ابزارهای اختیاری سیستم‌عامل در PHP قابل‌حمل جاسازی نشده‌اند؛ پیش از استفاده از این قابلیت، پشتیبانی میزبان را بررسی کنید. خروجی کارنامهٔ PDF فارسی با TCPDF همراه بسته از این ابزارها مستقل است.
